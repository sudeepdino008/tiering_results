Trade-off frontier

Each point is one (lookback, merge limit) run. Up and right is better. The connected points are the Pareto frontier: no other run beats them on both axes. The knee of that line is where the conclusion lives.

One row per run, the same window for all. Shaded cells are editable. Hot files = commitment files still on SSD at the end of the window; it is the hidden variable behind most of the knees.

Real data replaces the model with a CSV of lookback,merge_steps,ssd_saved_pct,mgas_s,commit_p95_ms,hot_files exported between each run's start and stop marks. The dummy model: saved space falls with longer lookback and with larger merge limits (a merged file waits until its last step is cold); throughput falls with shorter lookback (more HDD reads) and with many 1-step files on SSD (more index probes per lookup); the baseline is 150 Mgas/s and 95 ms p95.
